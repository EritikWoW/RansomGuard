RansomGuard 0.8.4.0 - audit-only quick start

Open UI\RansomGuard.Ui.exe normally.
Go to Settings -> Background monitoring -> Set up RansomGuard and approve UAC.
Choose explicit data folders, review the full paths, choose whether the service should start
immediately and/or with Windows, then use the reviewed Install or Install and start action.
The GUI does not require typing INSTALL, START, QUARANTINE or TRUST command tokens.

After setup, return to Overview and verify actual ETW monitoring health. SCM Running by itself
is not proof that filesystem telemetry is healthy.

Rules -> Add/Edit/Disable/Remove remain reviewed graphical UAC operations.
Stop previous run_audit consoles first; never kill processes by name.

The default normal product bundle does not install or load the Engineering LAB minifilter.
0.8.4 retains Engineering LAB/ProductionGate separation at protocol v18, the fail-closed hard-link
policy, and adds explicit mediation for reviewed data-mutating FSCTL paths, but the driver/GateClient lifecycle is still
not activated by the normal service; an Enforce request reports
EnforceUnavailable rather than claiming protection.
Default Audit operation remains non-blocking and is not production ransomware blocking.
Read UI_ADMINISTRATION.md and GUIDED_SETUP.md before administrative changes.

The UI is cryptographically paired to the published service bytes. Keep the complete package
together; do not mix an older service executable with a newer UI.
