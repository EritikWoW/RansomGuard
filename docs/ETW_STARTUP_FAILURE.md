# RansomGuard 0.6.3.0 — обработка отказа ETW

## Что исправлено
При отказе ETW (включая HRESULT 0x800705AA / Win32 1450) в обычном режиме служба
сохраняет канал read-only диагностики. UI показывает «Ошибка ETW» и прямо указывает,
что наблюдение файлов не работает. Этот релиз не устраняет лимиты ETW операционной системы.

Соединение со службой и доступность наблюдения теперь раздельные поля. Телеметрия
не подменяется нулями. Каталоги остаются настроенными, но не помечаются как наблюдаемые.
Подавление всех BackgroundService-исключений через Ignore не включено.

Автоматических повторов запуска, удаления трасс по префиксу, изменения EtwMaxLoggers,
выключения защиты Windows и блокировки обычных приложений нет.
Лабораторный запуск не начинает шифрование, если начальная инициализация ETW не удалась.
Если ETW отказывает уже во время лабораторного прогона, тест считается неуспешным;
сам факт отказа не останавливает уже работающий симулятор.

## Сначала диагностика (без пересборки)
В PowerShell от администратора:
```powershell
logman query -ets
```
Это запрос, не остановка сессий. Не используйте массовый logman stop или wpr -cancel.
Названия RansomGuardV032-* могут остаться от прерванных запусков; имя и отсутствие
одноимённой консоли сами по себе не доказывают, что сессию можно удалить.

В этой версии также есть `diagnose_etw.cmd`. Он сохраняет текстовый отчёт в %TEMP%,
показывает процессы/службы RansomGuard и результат `logman query -ets`.
Ничего в системе не останавливает и не меняет.
Если система давно не перезагружалась, после сохранения работы допустима обычная
перезагрузка и один запуск аудита. Это не гарантированное исправление: другие
программы могут заново занять сессии.

## Сборка
Распаковать в новую исходную папку. Не применять поверх старого release.
```powershell
.\build_windows.cmd
```
В новой release-папке:
```powershell
.\diagnose_etw.cmd
.\run_audit.cmd
```
Во втором обычном PowerShell:
```powershell
.\launch_ui.cmd
```

При неуспехе ETW:
- служба подключена;
- режим: Ошибка ETW;
- код: 0x800705AA;
- файловое наблюдение: недоступно;
- новый анализ файлов не производится.

После устранения причины завершить audit-консоль через Ctrl+C и запустить её снова.
Повторный запуск именно этой версии не выполняется автоматически.

## Проверка
В policy-harness добавлены тесты HRESULT/Win32 и разделения Running/Starting/Failed.
WPF smoke-test добавляет Dark-etw-unavailable.png и Light-etw-unavailable.png.
Здесь проверены структура исходников и ресурсы. C#/.NET, PowerShell, WPF и Windows ETW
в среде подготовки не выполнялись. Не называть такой тест проверенной Windows-сборкой.
